## 历史建议：SDK 报价的可释放终态

2026-09-27 核对 online 0.4.0 OpenAPI：`GET /open/sdk/generation-quotes/{id}` 提供 `submitted`、`expiresAt` 和不可变 `saleItems`，但没有取消入口、报价终止证明或逐分项“不再计费”状态。

示例已补齐事务预占，避免多次批准在扣款通知到达前重复使用余额。扣款事件与本地账务在同一事务处理，已扣分项不再占用额度；所有批准尝试均被明确拒绝时也能释放。网络不确定、已批准未提交或有未结算分项时则保留预占。

**这仍是 SDK 用户余额完整生命周期的发布依赖。** 仅凭浏览器关闭、生成终态、超时、`submitted=false` 或报价时间已过，不能证明没有在途提交或晚到的售价扣款。未取得平台权威证明前，不能增加一个定时释放任务来掩盖问题。纯 API 直接生成不走此预占流程。

下面内容可直接交给主项目：

```text
请补齐 SDK 0.4.0 报价及商户用户额度预占的释放合同，只修改主项目，不改 SDK 示例仓库。

背景：商户示例已实现批准前事务预占、按不可变 saleItems 逐项结算、重复请求/回调幂等和不确定响应保留预占。当前报价查询只有 submitted/expiresAt，无法安全释放“获批后浏览器关闭”“提交失败但没有售价事件”“部分分项最终不执行”等剩余额度。

请设计并实现平台权威的报价终止/取消或逐项结算状态接口/事件，接口命名由主项目确定，并更新 OpenAPI、SDK/API 文档与发布产物：
1. 未受理报价可幂等取消或过期关闭；与提交必须在同一并发控制边界内互斥。返回可释放证明后，任何旧批准/在途/重试都不能再产生该报价的新收费。
2. 已受理报价返回稳定 submissionNo，给出所有冻结 itemId 的结算状态；明确哪些仍可能计费、哪些已扣/已退、哪些永远不再计费。不能把“尚无结算记录”当成不再计费。
3. 查询与事件均绑定商户、externalUserId、quoteId、clientRequestId，并提供可幂等处理的事实版本/事件标识。已计费分项应附原 settlementId/金额或完整可补拉依据，处理事件乱序、重复、分页补偿和退款先到。
4. 保持原售价扣退合同：不可变 itemId 与原价、原 debit 关联、商户成本与用户售价分开；纯 API 直接生成不新增用户充值或 quote 要求。
5. 测试批准成功但响应丢失、用户关闭页面、过期与提交竞争、取消与提交竞争、部分未执行分项、终态先于扣退通知、宕机重启及重复通知。证明一旦发出释放事实，后续不能再出现未计入该事实的扣款。

交付：文档、迁移/发布顺序、测试证据、兼容性说明，以及商户后端何时释放每一项预占的确定规则。不要只写“超时释放”或让商户凭终态自行猜测。
```
