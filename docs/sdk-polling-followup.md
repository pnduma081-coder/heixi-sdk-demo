# 主项目 SDK 事件轮询历史补正说明

> 2026-09-25：以下提示词为历史排查记录。最新线上 SDK 文档已明确停止内嵌页自动事件订阅和宿主 onResult；不要据此重新启用已移除的订阅。当前接入以 `online-sdk-integration.md` 和线上版本文档为准。

本项目只能修改示例宿主，以下内容交由黑犀主项目处理；尚未修改或验证主项目线上行为。

## 可直接交给主项目的提示词

请优化 SDK 内嵌页面的生成结果事件轮询。当前 `apps/frontend/user-app/src/runtime/bootstrap-sdk.ts` 在桥接 ready 且结果订阅启用后，调用 `sdk-result-events.ts` 的 `startSdkResultEvents`，持续请求 `/sdk/client/events?limit=20`。空列表和请求失败仍固定等待 5 秒，没有空闲退避和页面隐藏暂停。

保留结果订阅、历史事件恢复与确认语义，按以下要求实现：

1. 打开 SDK 后先查询一次历史事件；不能仅凭当前页面没点生成就停止查询，否则会漏掉刷新前或其他页面提交的结果。
2. 无新事件时逐步降低查询频率，例如 30、60、120、240、300 秒。新任务受理、页面重新可见、连接恢复时立即唤醒；有正在运行的任务时保持合理的短间隔。对运行任务及超时给出明确判定，不用永久活动标记维持高频。
3. 页面隐藏时暂停自动查询，恢复时立即补查；保证同一订阅最多一个请求，不因重复唤醒启动多个循环。组件销毁时清理监听、定时器并取消请求。
4. 网络异常采用有上限的退避；鉴权失效沿用已有会话清理规则。有积压分页时保留有界快速消费，避免紧密空转。
5. 保持每个 SDK 结果等待宿主 `onResult` 完成后再推进游标。回调失败保留原位置重试，不能丢弃事件或重复生成、重复扣费。普通事件的消费与 SDK 结果确认仍按原合同区分。
6. 若通过刷新前历史事件或任务查询恢复活动状态，需确保旧任务能恢复、结束后能退出高频轮询，并验证并发唤醒与迟到响应不覆盖新状态。

请用独立数据验证：空账户闲置请求量、后台标签页零新增自动请求（允许已有请求收尾）、恢复可见立即查询、长任务期间及时通知、刷新后结果恢复、历史积压分页、宿主保存失败后恢复、断网重连、401/403 会话清理、换号及销毁后无旧请求继续运行。SDK 0.3.0 与 0.4.0 的宿主对接都需回归；内嵌应用由主项目提供，不能假定只影响新版本 SDK JS。

## 当前示例项目已处理

- 已移除 `/api/session` 的全局定时轮询，包括此前的空闲退避方案；页面空闲不再自动请求。
- 操作及 SDK 生成批准后立即刷新；并发刷新合并，在旧请求完成后补读，避免把操作前的状态作为最新结果。
- 首次进入、换号、进入本地数据页和点击“刷新账户数据”时按需读取。没有页面可见性触发的后台循环；卸载后停止，单次读取最多等待 15 秒。
- `/api/session` 是本示例的本地数据接口，不属于黑犀 SDK 合同，其他商户无需复制此接口或实现持续轮询。异步结算晚于操作回调时，可手动刷新查看；生产商户可按自己的业务采用消息推送或有明确起止条件的查询。
- 此修改不控制跨域 iframe 的 `/sdk/client/events`，也不停止示例服务端的持久事件消费。
