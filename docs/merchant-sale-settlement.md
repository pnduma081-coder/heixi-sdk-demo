# 商户成本、售价事件与历史账本

## 当前默认行为

本项目是 SDK/API 接入示例，不提供商户终端用户钱包、充值或预付费额度系统。

- 纯 API 新请求直接生成，平台按商户账户计费，不报价、不批准、不扣本地用户余额。
- SDK 新请求仍按协议读取权威报价，校验 `quoteId`、`clientRequestId`、`externalUserId` 和不可变 `saleItems`，保存报价快照后批准。浏览器传入的估价不可信。默认不根据本地余额拒绝，不创建预占。
- `credits.debited/refunded/license_debited` 记录为平台成本事件，不再创建本地用户余额变动。既有历史许可/成本扣款记录不改写。
- SDK 售价扣退仍按原始字节验签、按 eventId / settlementId 幂等、按 itemId / 原价 / originalDebitId 校验。新请求核对成功后记为 `RECORDED`，不扣本地余额。
- 回调早于报价或退款早于扣款时持久保存为 `PENDING`；条件齐备后处理。失败不确认成功，不猜金额，不按事件到达次序重复记账。

商户需要向自己的用户收费时，应在自己的计费系统接入批准策略与售价事件。充值、额度预占、取消释放和对账不属于本示例默认接入要求，也不是要求主项目扩展 API 的理由。

## 新旧请求的兼容规则

新增 `sdk_approval_policies` 与 `sale_quote_policies`，按请求号和报价号持久化策略，不依赖当前全局配置或浏览器参数：

| 策略 | 适用记录 | 行为 |
| --- | --- | --- |
| `AUDIT_ONLY` | 升级后新发起的 SDK 请求 | 权威报价校验后批准，售价事件只记录，无余额门槛、无预占 |
| `LEGACY_BALANCE` | 升级前已有 SDK 请求、报价及旧 API 报价恢复 | 保留原余额校验、预占及实际售价扣退，避免原任务变更记账方式 |

迁移只增加策略标记，不删除表、不修改历史余额、不撤销已发生的扣退、不释放尚未确定的旧预占。新请求不会被旧余额或旧预占限制；旧记录在“历史演示账本”中单独查看。已受理请求返回原响应，超时恢复原请求号，不以新编号重提未知任务。

历史的预占与批准尝试代码仅用于兼容旧请求，不作为新请求默认策略。原批准已成功或结果未知时，旧预占仍保留；它不是本项目新请求的额度，更不阻塞 SDK/API 接入示例的发布。不要手动清库、加钱或猜测取消来改写历史账务。

旧 `/api/credits` 接口保留给历史演示账本恢复，不再提供默认充值 UI，也不是新请求的前置要求。

## 页面展示

“消耗记录”分开显示平台成本和售价事件，明确区分“已记录（未扣本地余额）”与“已按历史规则入账”。历史演示余额、流水与未结算预占只放在折叠的历史区域。

SDK 的 `credits` 仍是必填展示字段，0 是合法值。本示例传 0 并设置 `showHeader:false`，隐藏 SDK 的余额/充值顶部栏，不虚构商户余额；该顶部栏内的历史按钮也随之隐藏；页面编辑工具、结果区域和刷新恢复保留。商户如需自己的余额展示，可按官方合同启用顶部栏并通过 `sdk.update` 同步自有系统数值。

## 验证与持久恢复

独立回归覆盖零余额并发批准、事件只审计、报价/退款/扣款乱序、重复 eventId/settlementId、原价与身份冲突、重启不改变策略、迁移不改历史余额，以及旧请求预占/扣退原规则恢复。

后台原始事件与接收游标同事务保存，单项失败独立重试，浏览器关闭不影响处理。新旧策略共用事件幂等机制，原始事实保留。已撤回的预占释放接口建议见[历史说明](sdk-reservation-followup.md)。
